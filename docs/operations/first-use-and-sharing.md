# 研究室で共有するための初回利用ガイド

## 入手するもの

[公式Release一覧](https://github.com/Xpotato1024/Selfrionette-Device/releases)からSelfrionette Device ManagerのWindows x64用setup.exeを取得する。Rust、Node.js、Python、Gitや開発用cloneは不要。ZIP版は全体を展開して使用する。

配布されるソフトウェアと、USB接続するSelfrionette入力装置は別のもの。Device Managerは入力確認、装置設定、個人校正、Firmware更新を行うアプリである。Xpotato-Simそのものは含まない。

## まず旧Firmwareのまま入力を確認する

入力装置を接続し、「接続先を選ぶ」で実際の基板を明示する。受信監視はFirmwareを書き換えない。vector形式の値が見えてもFirmware名・版が判明したとは限らず、「未取得・不明」は正常な区別である。

旧版で値を見るだけなら個人校正は不要。新しい個人用補正を使う場合にManaged Firmwareへ進む。分からない状態で手動のinfoコマンドを送らない。

## Firmwareを更新する

1. 「調整」から「Firmware更新」を開く。入力確認や他のシリアルツールが接続中なら、先に接続を解放する。
2. 対象基板、書き込む系統、同梱/ローカルpackageを選ぶ。通常の新しい管理機能には **Selfrionette Managed** を使う。Originalは初期保管、Compatibleは互換改善の用途であり、Managedの別Protocol番号ではない。
3. 検査結果を開き、現在確認できた本体版、書込むFirmware名と配布版、対応通信Protocol、保護記録、対象基板を確認する。Original/Compatibleの配布版1.0.0は後付け識別名で、本体の版照会機能はない。
4. 対象と書込みを明示確認して開始する。進捗バーと「対象確認→待機モード切替→書込み→照合→再接続確認」を確認する。数字が出ない工程は不定進捗であり、停止と決めつけて抜線しない。
5. 書込み工程の100%だけでは更新完了ではない。全域照合と更新後の確認が終わるまでUSBを抜かず、アプリを開いたままにする。対象を結び付けられない場合は同じ実物のbootloaderを追加確認する。

「要復旧」なら、別の基板へ再試行せず表示された保護記録を保持する。「確認・復旧」は状態の読戻しであり、自動で再書込みする操作ではない。分からない場合は配布版・対象・画面の結果と技術情報を管理者へ渡す。アプリデータを削除しない。

## Managedで個人用設定を保存する

「装置と取付方向」で個体IDと実配線・正方向を確認する。その後、無荷重tareと自然な操作姿勢での中立を別に取得し、「個人校正」で正負方向、弱い力、同時入力、除荷を検証して保存する。未知の方向を推測して埋めない。

個人設定はPCの %APPDATA%\dev.selfrionette.manager\personal-profiles\<device-id>\ に保存する。Firmwareに保存される装置ID・極性等とは別で、個人の感度・干渉補償を装置に書き込む設計ではない。

通常利用時はGUIを終了できるが、補正計算はPCの共通Rust機能を利用する。再接続時のtare/中立は取り直す。Firmware版・装置設定・姿勢・操作者が変わると古いprofileが不適合になる場合があり、再検証/再校正が必要。ファイルが保存されていることと、今回適用できることは別である。

Xpotato-Simへの品質付き入力統合は別プロジェクトの #631 の作業で、Managerの配布だけでSim統合済みとはならない。

## 配布と検証の範囲

本配布の対象はWindows 11 x64、Pro Micro互換ATmega32U4・16 MHzの指定構成。異なる基板へ書き込まない。アプリは現在デジタル署名されておらず、表示される発行元名だけでWindowsの確認済み署名になるわけではない。セキュリティ機能を無効にする必要はない。

ReleaseのBUILD-INFO、ハッシュ、検証記録にはソフトウェアの検証範囲を記載する。自動試験は実機への書込み・EEPROM電源断耐性・荷重精度・操作安全の認証ではない。現物の状態が不明な場合は研究室の管理者と確認してから更新する。
