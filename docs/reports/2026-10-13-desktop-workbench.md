# デスクトップ配置・短い検証サイクル

基点はPR #12 / adae481。署名と実機の通信/校正/EEPROM/Firmware書込みは変更しない。コード署名は後回しとの利用者指示に従う。

## 実装した範囲
- 任意の狭幅に縦積みするCSSと縦手順の自動折畳みを廃止。1100×720初期/800×520最小の論理サイズ、上部操作と作業タブは固定し、作業ペインを伸縮/スクロール。
- 七行のDOMを保持し、符号/整数/小数部/指数の領域を固定。小数2桁と桁あふれ境界の指数表示。失効時も同じセルに—。
- 左22remの読み取りペインと、余った幅/高さを使う表示履歴ペイン。表示用サンプル、30秒/最大200点。受信全件のデータ記録ではない。
- 入力確認等の重複したページ見出しを視覚的に削除（アクセシブルな見出しは維持）。
- check:fastで単体/配布条件/動的UIを並列実行。通常のUI変更はRustとNSISを作らない。
- CIのcodex push + PR二重起動を除去。変更範囲の選択、依存/中間出力キャッシュ、配布buildとverifyの分離。
- 製品入力fingerprintとSHA-256により、同じバイナリを別の検証job/checkoutで再試験。元のsource_commitを保持。

## ローカルの確認
高速検証は合計16.36秒（unit 0.18秒、tooling 2.25秒、dynamic UI 16.35秒の並列）。Rust build/NSIS生成は0回。単体16件、配布/CI条件24件、表示幅800/1100/1600 × deviceScaleFactor 1/1.5/2の9組でPASS。
動的表示では符号/桁変化/小数/指数/受信失効に対する小数点位置、行のDOM同一性、表の矩形維持を確認した。
Windows Debug/Tauri/Rust IPCの既存9群もPASS（run-k1w41v）。型付き操作・保存/失効・履歴・取消の既存assertionを維持。従来320/640のreflow試験は、新しいデスクトップ契約の3サイズと縦手順常設の検査へ置換した。
最後の丸め境界の補強はreadoutの単体試験で再確認。配布候補の最終headの全結果はPRとCI artifactを正とする。

## 未完・制約
接続操作を含むコード更新がツール側でブロックされたため、接続先選択フローの全面変更・poll中のbusy状態分離は実行していない。既存の接続選択/確認/直列化を維持し、独立した表示と検証基盤だけを変更した。
Tauri/WebView2を維持しており、WinUI等のOSコントロールへの移行ではない。実WindowsのDPI切替、文字サイズ設定、スクリーンリーダー、対象実機の連続受信は未検証。画素密度の模擬値を実DPI受入とは呼ばない。
署名は未対応のまま。全体の改善率やwarm-cache効果は未測定で、16.36秒を配布全工程の時間とは比較しない。
